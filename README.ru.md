# citilink-mcp

[English](README.md) · **Русский**

[MCP](https://modelcontextprotocol.io)-сервер, который отдаёт LLM-агентам живые
и честно подписанные данные [Ситилинка](https://www.citilink.ru) — крупного
магазина электроники и бытовой техники: поиск с настоящими страницами,
сортировками, ценовым окном и фильтром наличия; полная карточка товара для
выбранного города; рейтинг самого товара рядом с рейтингом группы вариантов;
магазины и пункты выдачи Ситилинка; отзывы; вопросы и ответы; уценка и б/у.

Обычный HTTP к собственному GraphQL сайта — без браузера и без аккаунта.

## Зачем этот сервер

Данные Ситилинка легко получить и легко неверно прочитать. Сервер устроен так,
чтобы не выдавать цифры, которых покупатель в вашем городе не увидит:

| Ловушка Ситилинка | Что делает сервер |
|---|---|
| Город живёт в «липкой» куке; старое или неверное значение молча даёт цены Москвы | Ставит город на каждый запрос и сверяет город, для которого, по словам Ситилинка, посчитан ответ; ответ для другого города повторяется один раз, затем отвергается |
| Цена, клубная цена, зачёркнутая цена, ассортимент, остатки и доставка зависят от города | В каждом ответе `city` (эхо самого Ситилинка и откуда взят город) и `fetched_at` |
| В API есть клубная цена, даже когда сайт её не показывает (`clubPriceViewType: SKIP`) | Клубная цена отдаётся только когда её показывает сайт, и всегда подписана как условная (для участников Клуба со входом) |
| Пустая строка цены (`""`) — собственный код сайта превращает её в «0» | `price_rub: null` с причиной, никогда не 0 |
| Бонусы («До 537 бонусов») выглядят как скидка | Отдельное поле: баллы на будущие покупки, из цены не вычитаются |
| Товары, которые продаются только коробкой: крупная цифра на сайте — `цена × 10` | `price_rub` за штуку плюс `lot` с ценой лота, зачёркнутой и клубной ценой ровно как на странице |
| В плитках выдачи и шапке карточки — рейтинг всей группы вариантов (1, 2 и 4 ТБ вместе) | `rating.this_product` (отзывы именно этого товара) рядом с `group` / `group_shown_on_site`, с полем `scope` |
| «Самовывоз из 1560 магазинов» — 1548 из них партнёрские точки в нескольких регионах, часть с платной доставкой до точки | Свои магазины и пункты выдачи Ситилинка — списком с датами; партнёрские — только подписанной сводкой с числом платных и диапазоном цены |
| `perPage` больше 48 молча режется до 48, а `totalPages` после этого врёт | Страницы всегда по 48; `has_more` считает сервер |
| Числовой id сортировки молча игнорируется (остаётся релевантность) | Сортировки передаются slug-ами; сервер проверяет, применил ли Ситилинк сортировку, ценовое окно, наличие и категорию, и отвергает ответ, который их проигнорировал |
| Несуществующий id молча пропадает из пакета, а слишком длинный обнуляет весь пакет | Id проверяются до запроса; неизвестные попадают в `not_found` |
| В групповом режиме у всех отзывов стоит `fromGroup`, даже у отзывов самого товара | Отзыв сообщает, о каком другом варианте он написан (`other_variant`), по id товара в отзыве |
| Фильтр по звёздам пересчитывает сводку (товар с 4,9 показывает 3,8) | Заголовочные рейтинги в `get_reviews` всегда без фильтра |
| Отзывы, импортированные с Яндекс Маркета, смешаны с отзывами Ситилинка | У каждого отзыва есть `source`; импортированные подписаны как непроверенные покупки |
| Даты приходят как полночь UTC | Отдаются календарными датами (`YYYY-MM-DD`) без сдвига часового пояса |
| Собственный JS-челлендж Ситилинка (HTTP 429 + страница со скриптом) теперь бывает и на API | Решается на Python один раз за вызов (без выделения 512 МБ), кука хранится свой час; повторный челлендж — ошибка, а не цикл |
| Ответ GraphQL может нести данные и ошибки одновременно | Данные сохраняются, сбойные поля перечислены в `partial_errors` |

## Инструменты

| Инструмент | Что возвращает |
|---|---|
| `search_products(query, page, sort, price_min, price_max, category_id, availability, limit, city)` | 48 товаров на страницу; сортировка `relevance` / `price_asc` / `price_desc` / `discount` / `rating` / `opinions`; наличие `any` / `in_store_now` / `pickup` / `delivery`; `total_found`, `has_more`, `price_range_rub` (границы ценового фильтра сайта), `categories` (id, slug, количество). По товару: цена, зачёркнутая, клубная (если показана), бонусы, лот, рейтинг товара и рейтинг группы, штук в магазинах зоны, ближайшая дата самовывоза, метки, промокоды, признак уценки, ссылка |
| `get_product(product, include_specs, include_stores, city)` | Всё перечисленное плюс условия оплаты (предоплата, кредит, рассрочка), распределение звёзд товара и группы, ИИ-выжимка отзывов от Ситилинка, партномер (`mpn`), модель, гарантия, страна, варианты с id, цена и дата курьера, даты самовывоза, магазины и пункты выдачи Ситилинка, сводка по партнёрским точкам, состояние уценки, акции, все характеристики |
| `get_reviews(product, page, limit, sort, scope, stars)` | Дата, звёзды, достоинства, недостатки, текст, вариант, источник, голоса; `scope=product` (по умолчанию) или `group`; `sort=worst` ставит жалобы первыми; фильтр по звёздам |
| `get_questions(product, page, limit, sort)` | Вопросы с ответами в виде тредов; ответы экспертов Ситилинка и представителей бренда помечены; имён авторов нет |
| `find_markdown(category_slug \| product, page, sort, city)` | Уценка и б/у в категории или конкретного товара: цена, причина, комплектация, износ, повреждения, гарантия, id нового товара, дата самовывоза |
| `compare_products(products, city)` | До 20 товаров рядом одним запросом, с `not_found` и `invalid` |
| `resolve_city(name)` | Id городов по справочнику Ситилинка (8465 городов), например `Березовский` → два города в двух регионах |

`product` — id (`1896626`), id уценки (`M00295786`) или ссылка на товар.
`city` — id (`ekat_cl`, `ekat_cl:5x0029236`) или название (`Екатеринбург`, `Кировск, Мурманская`).

## Требования

Замерено на Linux (CachyOS, Python 3.12, домашний интернет в России):

| | |
|---|---|
| Python | ≥ 3.10 и [uv](https://docs.astral.sh/uv/) (или pip). Зависимости: `mcp`, `requests` |
| Браузер | **Не нужен.** Ни Playwright, ни Chromium |
| Docker | Не нужен |
| Дисплей | Не нужен |
| Память | ≈ 73 МБ резидентной памяти в покое, ≈ 84 МБ в пике после поиска на 48 товаров и полной карточки |
| Холодный старт | 0,5 с от запуска до списка инструментов через `uvx`, когда пакет уже собран; 1,4 с при самом первом запуске (сборка). При установке из GitHub к каждому старту добавляется `git fetch` от uv |
| Диск | ≈ 40 МБ окружение uv; ≈ 1,2 МБ кеш (`~/.cache/citilink-mcp`: справочник городов и куки сессии) |
| Время запроса | 0,1–1,1 с на запрос к Ситилинку (поиск на 48 товаров 0,7–1,1 с, однажды 2,9 с; полная карточка 0,2–0,7 с; отзывы и вопросы 0,1–0,3 с) плюс пауза 2,5 с между запросами |
| Сеть | Российский IP. С домашнего IP всё работает; по стороннему отчёту, датацентровые IP получают HTTP 429 на весь домен (здесь не проверялось). При необходимости — `CITILINK_PROXY` |

## Установка

Claude Code:

```bash
claude mcp add citilink -- uvx --from git+https://github.com/SZhukovWork/citilink-mcp citilink-mcp
```

Любой MCP-клиент (`claude_desktop_config.json`, `.mcp.json`, …):

```json
{
  "mcpServers": {
    "citilink": {
      "command": "uvx",
      "args": ["--from", "git+https://github.com/SZhukovWork/citilink-mcp", "citilink-mcp"]
    }
  }
}
```

Из рабочей копии: `uv venv && uv pip install -e . && .venv/bin/citilink-mcp`
(или `uvx --from /путь/к/citilink-mcp citilink-mcp`).

## Настройка (переменные окружения)

| Переменная | По умолчанию | Что задаёт |
|---|---|---|
| `CITILINK_CITY` | `ekat_cl` (Екатеринбург) | Город по умолчанию: id или название (`Екатеринбург`, `Москва`, `Березовский, Свердловская`). Название стоит одного запроса за справочником городов Ситилинка, дальше он неделю берётся из кеша; неоднозначное название — ошибка со списком вариантов. Аргумент `city` важнее |
| `CITILINK_MIN_INTERVAL` | `2.5` | Секунд между запросами к Ситилинку (плюс до 0,5 с случайно). Вызовы параллельных агентов встают в очередь |
| `CITILINK_PROXY` | — | URL прокси, например `http://user:pass@host:3128` |
| `CITILINK_CACHE_DIR` | `~/.cache/citilink-mcp` (с учётом `XDG_CACHE_HOME`) | Справочник городов (обновляется раз в неделю) и куки сессии (файл 0600, каталог 0700) |

## Что означают цифры

- **`price_rub`** — обычная цена, которую видит любой посетитель сайта без
  входа в аккаунт, в городе из `city`. `null` и `price_note`: Ситилинк сейчас
  не продаёт товар в этом городе.
- **`old_price_rub`**, **`discount_percent`** — зачёркнутая цена и скидка, как
  на сайте; нет поля — нет зачёркнутой цены.
- **`club_price_rub`** — клубная цена Ситилинка: применяется при оформлении
  заказа со входом и Клубной картой (карта выдаётся при бесплатной
  регистрации). Условная, поэтому никогда не заменяет `price_rub`. Отдаётся
  только когда её показывает сайт (тип `PRICE_IN_RUB`, сверено с отрисованной
  страницей); типы `DIFF_IN_RUB` / `DIFF_IN_PERCENT` / `WANT_TO_KNOW` подписаны
  по коду рендера сайта с пометкой «not seen live».
- **`bonuses`** — баллы Клуба на будущие покупки: `base` (базовый статус),
  `extra_for_sbp_payment` (за оплату через СБП), `site_shows_up_to` (цифра «До N
  бонусов»). Это не скидка на товар.
- **`lot`** — товар продаётся только лотами. Крупная цифра на сайте — цена
  лота (сверено со страницей: «3050 ₽ · 305 ₽×10 шт. в коробке · Клубная цена
  2430 ₽ · До 50 бонусов»); `price_rub` остаётся за штуку.
- **`promo_codes`** — метки вида «Промокод ИГРАЙ −2000₽»: вводятся при
  оформлении, сервером не проверены и из цены не вычитаются. `payment.credit` /
  `installment` — условия кредита, а не цена. `prepayment_required` — сайт
  требует предоплату («Предоплата»).
- **Рейтинги** — `rating.this_product`: отзывы именно этого товара (вкладка
  «Этот вариант товара»); `group` / `group_shown_on_site` / `shown_on_card`:
  все варианты группы (вкладка «Все отзывы» по умолчанию и цифра в плитках).
  Товар без вариантов — сам себе группа. Рейтинг `null` — отзывов пока нет.
  `site_review_digest` — машинная выжимка отзывов от Ситилинка.
- **Наличие** — `units_in_city_stores`: штук на полках магазинов Ситилинка в
  зоне доставки города прямо сейчас (`">50"` — формулировка самого сайта). 0 не
  исключает самовывоз сегодня: товар везут и со склада. `pickup` /
  `pickup_earliest_date`: даты, когда товар можно забрать. `own_stores`:
  собственные магазины и пункты выдачи Ситилинка с датами и
  `units_in_store_now`. `partner_points`: точки других компаний по всей зоне
  доставки (несколько регионов), `paid_count` из них — с платной доставкой.
  `courier`: цена «от» и дата для города; итоговая сумма зависит от адреса.
- **Уценка** — id начинается с `M`, название оканчивается на «(Б/У)»: бывший в
  употреблении или повреждённый экземпляр. `condition` / `markdown` цитируют
  Ситилинк: причина, комплектация, износ, повреждения, гарантия (часто
  1 месяц). `original_product_id` — новый товар.

## Ограничения

- **Неофициальный.** Сервер пользуется внутренним GraphQL витрины, который
  Ситилинк может изменить в любой момент. Запросы минимальные, каждое поле
  проверено живьём; изменение схемы даёт понятную ошибку `SchemaChanged` с
  именем поля.
- **Только цены для анонима.** Персональные цены, закрытые акции и ваш
  процент бонусов требуют входа; сервер в аккаунт не входит. Совпадает ли
  клубная цена с суммой при оформлении — не проверялось.
- **Нет истории цен, продавцов и штрихкодов.** Публичной истории цен у
  Ситилинка нет, продаёт он сам (маркетплейса нет), EAN в характеристиках не
  публикует; партномер (`mpn`) и модель есть.
- **Промокоды** показываются только как метки; условия — Ситилинка.
- **Несверенные типы отображения.** Типы клубной цены `DIFF_*` /
  `WANT_TO_KNOW` живьём не встретились; подписи взяты из кода сайта.
- **Фасеты поиска — ситилинковские.** `availability=in_store_now` — это фильтр
  сайта «Забрать через 5 минут», в нём бывают товары с 0 штук на полках;
  `total_found` может быть больше счётчика категории (по-видимому, считает и
  товары не в наличии).
- **Антибот.** JS-челлендж Ситилинка решается на Python; если его разметка
  поменяется, сервер скажет об этом, а не будет угадывать. Датацентровые и
  VPN-адреса могут получать отказ (HTTP 403/429).
- **Троттлинг.** Запросы идут по одному и с паузами; при ограничении частоты
  сервер один раз ждёт и затем сообщает об этом — ждите минуты, не повторяйте в
  цикле.

### Если Ситилинк начнёт требовать `x-ad-mark`

Собственный GraphQL-клиент сайта (модуль Rust/WASM) добавляет к каждому
запросу заголовок `x-ad-mark`. Сейчас Ситилинк его не проверяет. Если начнёт,
сервер ответит «Ситилинк начал требовать подпись запроса (x-ad-mark); нужен
запасной путь из README» с кодом HTTP. Запасные пути (план):

1. Запускать сайтовый `graphql_bg.wasm` в Node с небольшими заглушками — его
   импорты только `fetch`, `getRandomValues`, `location.origin`, `Headers` и
   `JSON.stringify`, так что браузер не нужен.
2. Как в [ozon-mcp](https://github.com/SZhukovWork/ozon-mcp): долгоживущая headless-страница, которая вызывает
   собственный клиент сайта (≈ 1,3–1,8 ГБ памяти на Chromium, ≈ 1 с на переход).

## Планы

- Необязательный режим аккаунта (ваши персональные цены, клубная цена и
  процент бонусов) и корзина — позже.
- Оформление заказа, оплата и смена адреса — вне планов.

## Разработка

```bash
uv venv && uv pip install -e '.[dev]'
.venv/bin/pytest            # офлайн-тесты на записанных ответах
.venv/bin/pytest -m live    # сквозной прогон по MCP stdio против живого citilink.ru (11–12 запросов, ~35 с)
```

Парсеры — чистые функции в `parse.py`; политика запросов — `analyse()` в
`client.py`; GraphQL-запросы — в `queries.py`. Фикстуры в `tests/fixtures/` —
настоящие ответы, записанные один раз: тест проверяет, что в JSON-фикстурах нет
имён авторов, кук и HTML страниц, а в записанной странице антибот-челленджа
куски куки заменены заглушками.
